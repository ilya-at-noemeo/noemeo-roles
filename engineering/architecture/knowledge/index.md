# Architecture Role — Knowledge Index

Accumulated knowledge specific to the architecture role: decisions made,
rationale, and learnings from actually building things. Distinct from
[`../../architecture.md`](../../architecture.md) (the role's static
definition -- scope, judgment lens, boundaries), which should stay stable.
This index grows as the role does work; the definition doesn't need to
change just because the role has learned something.

## How to add an entry

1. Write the actual content as its own file in this directory
   (`<topic>.md`), not inline here. Keep this index scannable.
2. Add one line below linking to it: `- [Short title](topic.md) — one-line
   description of what it covers and why it matters.`
3. If the entry resolves or supersedes an earlier one, update or remove
   the earlier entry rather than leaving contradictory guidance both
   still listed.
4. If a GitHub issue prompted this entry, reference the issue number for
   traceability, but the entry itself should stand on its own -- someone
   reading only this file, not the issue, should still get the point.
